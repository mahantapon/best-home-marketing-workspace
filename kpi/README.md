## ข้อมูลและการเชื่อม

Roadmap เป็นสำเนาแผนล่าสุดจากปฏิทิน MARKETING ที่ตรวจวันที่ 16 พ.ย. 2569 และข้อมูลสัปดาห์จากแผนฉบับ 13 พ.ย. รุ่นที่เก้าตอบแล้ว ไม่มีการดึงข้อมูลเซิร์ฟเวอร์หรือกุญแจเข้าหน้าเว็บ และไม่ได้ส่งการแก้ไขกลับปฏิทินต้นทาง

รหัส PLAN เดิมเป็นกุญแจของงานแต่ละชิ้น สถานะและหลักฐานอยู่ชุดเดียวใน `roadmapRecords` ทุกหน้าจึงใช้ข้อมูลตรงกัน รอบประเมินใช้ช่วงกำหนดส่งที่เลือก หนึ่งงานที่ใช้หลายแพลตฟอร์มนับครั้งเดียว

การเชื่อมนี้ทำงาน **ภายในเบราว์เซอร์เดียวกัน** ไม่มีบริการบันทึกร่วมข้ามเครื่อง ผู้เปิด URL คนละเครื่องมีข้อมูลของตนเอง ผลประเมินไม่ถูกอัปโหลด GitHub ชื่อและผลงานจริงไม่มีในข้อมูลเริ่มต้น

## เริ่มใช้

1. เปิด Roadmap เลือกสัปดาห์และเปิดงานที่ต้องการ
2. ตกลงวันส่งร่างและวันส่งครบ เลือกให้งานนับใน KPI ของน้อง (วันเผยแพร่ไม่ได้เป็นวันส่งงานโดยอัตโนมัติ)
3. บันทึกวันส่งจริง ลิงก์ไฟล์ คุณภาพร่างครั้งแรก และจำนวนรายการจัดเก็บ
4. หน้า KPI เลือก `เชื่อม Roadmap` และช่วงวันประเมิน การพัฒนาวิธีทำงานกรอกแยกพร้อมหลักฐาน

รอบใหม่ใช้โหมดเชื่อม Roadmap; รอบเก่าคงค่ากรอกเองไว้ สลับกลับมาได้โดยไม่ทับคะแนนเก่า เป้าและน้ำหนักเดิมยังอยู่

## สูตรและข้อมูลที่ยังไม่ครบ

- ส่งครบ: งานที่ส่งครบจริงภายในวันตัดข้อมูล ÷ งานที่กำหนดส่งครบอยู่ในรอบและถึงวันตัดข้อมูล
- ตรงเวลา: วันที่ส่งร่างจริงไม่เกินวันส่งร่างที่ตกลง งานที่ยังไม่ถึงกำหนดไม่นับ
- คุณภาพ: ข้อที่ผ่านจากร่างแรก ÷ ข้อที่ตรวจแล้ว ข้อไม่ใช้ไม่รวม; ยังไม่ตรวจขึ้นรอตรวจและคะแนนชั่วคราว
- จัดเก็บ: รายการครบตามกำหนด ÷ รายการที่ต้องมี ไม่มีข้อมูลไม่แทนด้วยศูนย์
- พักตามข้อตกลงต้องระบุเหตุผล จึงตัดออกจาก KPI; ติดขัดอย่างเดียวไม่ตัดอัตโนมัติ
- รอบเก่าตัดวันที่ผลจริงที่วันสิ้นสุดรอบ ไม่เอางานส่งหลังรอบมาให้คะแนนย้อนหลัง
- สรุปคะแนนเฉพาะน้ำหนักที่มีข้อมูล ระบุความครอบคลุมและรอตรวจเสมอ ไม่มีเกณฑ์ผ่าน/ไม่ผ่านอัตโนมัติ

## สำรองและนำเข้า

JSON รวมทุกรอบและสถานะ Roadmap CSV รวมคะแนนรอบที่เลือกและหลักฐานงาน 96 ชิ้น
นำเข้าเพิ่มรอบใหม่โดยเก็บรอบเดิม หากรหัสงาน Roadmap ซ้ำแต่ผลต่างกัน จะเก็บข้อมูลเครื่องนี้ไว้และแจ้งจำนวนที่ต่างกัน จึงไม่ใช่การซิงก์ร่วมแบบเรียลไทม์
อ่านไฟล์สำรองรุ่นเดิมได้ หากอ่านข้อมูลไม่ได้จะไม่เขียนทับ มีปุ่มสำรองข้อมูลดิบก่อนเริ่มใหม่ การแก้ต่างแท็บจะแจ้งให้โหลดข้อมูลล่าสุดก่อนเขียนต่อ

## ตรวจและ build

`npm test` ตรวจสูตรเดิม สูตร Roadmap การสำรองรุ่นเก่า/ใหม่ และงานจัดลำดับเดิม
`npm run build` รวม `kpi/` ใน `dist/` ด้วย GitHub Pages ใช้ `main` ที่ root

ฟอนต์ LINE Seed Sans TH และใบอนุญาตเดิมใน `assets/fonts/` ดีไซน์ใหม่ใช้พื้นที่ขาว สีเทาอ่อนและม่วง อ้างอิงโครง Workly KPI Dashboard ที่เก้าระบุ
